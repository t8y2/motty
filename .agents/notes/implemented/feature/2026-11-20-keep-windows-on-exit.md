# Agent Note: 退出时保留窗口

Status: implemented

## Problem

Motty 退出时总会把每个窗口的记录留在 `config.db`，下次启动按记录恢复所有窗口和标签。对同时开很多窗口的用户，退出后这些窗口会原样回来；想从干净状态开始的用户只能在下一次启动后逐个关掉。现有设置只有「关闭窗口时」决定留在托盘还是退出，没有决定**退出后是否保留窗口记录**的选项。

## Decision

- 设置 › 通用新增「退出时保留窗口」，落盘键 `keep_windows_on_exit`，值 `always` / `never` / `ask`，缺省 `always`：默认行为与旧版本一致。该设置属于本机，不进入同步。
- `windowSet.quitWithDocuments` 是退出命令（托盘 Quit、窗口菜单退出、macOS Quit 请求）的统一入口。它先处理未保存文档，再按设置决定保留还是丢弃窗口记录；`ask` 时只在仍有窗口的情况下询问，问完才设置 `quitting`。
- 「不保留」通过 `State.DropWindowRecord` 删除每个窗口自己的记录。窗口关闭时 `State.Close` 仍会先保存一次，所以删除必须在 `OnClosed` 里、`Close` 之后执行，不能只在退出前清一次记录——否则最后一个关闭的窗口会把记录又写回来。
- 「询问」使用独立的 `modalQuitKeepWindows` 对话框，标题「保留窗口？」，三个动作是「保留并退出」「不保留并退出」「取消」。取消只关闭问题，不退出；再次触发退出不会替换已经打开的问题。
- 关闭最后一个窗口和退出命令一样会结束程序，因此也走同一套判断：`ask` 会先问，`never` 会丢弃记录；关闭仍有其他窗口的单个窗口仍只丢弃它自己的记录。
- 记录仍然是窗口级的：每扇窗口保留自己的标签和位置，退出策略只决定这些记录是否在退出时删除，不改变多窗口恢复格式。

## Alternatives considered

### 为什么不在保存时直接跳过窗口记录？

在 `State.save` 里根据「退出时丢弃」标志跳过窗口记录，可以让退出前不需要再打开一次配置库。但窗口记录同时用于窗口拖动后的增量保存；用一个只对退出有效的标志去改 `save` 的写入路径，会把「保存失败后的重试」「另一个窗口并发写同一记录」这些既有约束卷进来。继续沿用 `DropWindowRecord` 的删除路径，复用的是用户关闭单个窗口时已经验证过的语义。

### 为什么询问不复用现有表单对话框？

现有 `formDialog` 的固定动作是「提交 / 取消」，第二个选择只能用 `back` 回调伪装，按钮语义和焦点行为都不对。退出确认需要明确的三个动作，独立对话框让「保留」「不保留」「取消」各自有稳定的 hit id，也方便键盘和测试。

### 为什么不做成同步设置？

「退出时是否保留窗口」描述的是这台电脑下次启动时的窗口布局，和 `close_action`、启动项一样属于本机行为；同步到另一台设备会让那边的窗口被这里的退出策略影响，和现有本机设置的边界不一致。

## Consequences

- 收益：默认仍保留窗口；不想保留的用户可以让下次启动只按启动项打开一个新窗口；需要时可以选择每次退出前确认。
- 代价：设置页通用分组多一行；`ask` 多一个模态对话框，退出路径从一次 `application.Quit` 变成「确认文档 → 确认保留 → 关闭窗口」。在不使用托盘、关闭最后一个窗口即退出的桌面上，这条路径同样会多一次询问。
- 边界：选择「不保留」不会删除配置里的主机、标签模板或其他状态，只删除窗口记录；崩溃退出不会经过退出命令，因此下一次启动仍可能恢复上次的窗口记录。
- 测试：`quit_windows_test.go` 覆盖策略字符串、询问的保留/丢弃/取消回调、设置持久化；`settings_test.go` 覆盖设置行可用键盘切换；`window_records_test.go` 既有的记录压缩/删除测试继续覆盖记录本身。
