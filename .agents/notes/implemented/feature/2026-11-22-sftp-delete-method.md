# Agent Note: SFTP 删除方式选择与强制删除

Status: implemented

## Problem

issue #1313：文件面板删除文件时只有一个确认框，用户无法区分「普通删除」和
`rm -f` 式强制删除。普通删除在递归删除文件夹时遇到第一个失败就停止，后面的
条目不再尝试；而实际使用中，一个只读或刚好被其他进程占用的条目不应阻止其余
条目删除。另一个问题是删除大量条目时，分离的文件窗口状态栏只有文字，没有
转圈指示，用户容易以为操作已经结束。

## Decision

- 现有删除确认框增加「删除方式」选择：`普通删除` 和 `强制删除（rm -f）`，
  默认普通删除。普通删除保持原有语义：遇到第一个失败立即停止，结果说明已删除
  的内容和失败位置。
- 强制删除的语义固定为 `rm -f` 中可移植的那部分：某个条目失败后继续处理其余
  条目，已经不存在的条目按已删除处理；服务器仍然逐条决定 unlink 是否允许，
  不做权限绕过。选择强制删除后再弹一次确认，说明它会继续处理其余项目。
- 删除方式只作用于本次操作，不写进设置。普通删除是安全默认值；强制删除是
  一次性的破坏性选择，不应成为下一次删除的默认。
- 本机文件走同一套语义：普通删除在第一个失败处停止，强制删除继续并忽略已不
  存在的条目。符号链接始终只删链接本身，不跟随到目标。
- 远端删除仍通过 SFTP worker 执行，不额外启动 shell。递归删除保留原有的
  深度上限、条目数量上限和取消检查；强制删除遇到取消、路径穿越或超出上限时
  立即停止，不会为了「继续」而忽略安全边界。
- 删除期间底部状态栏显示转圈指示：停靠面板沿用已有 spinner，分离窗口的状态
  行补上同样的 spinner；多选删除显示「正在删除第 i/n 个项目…」，而不是反复
  只显示第一个名字。
- 结果新增 `Removed` 和 `Failures` 计数：前者是实际离开服务器的条目数（包含
  文件夹内的条目），后者是强制删除未能删除的条目数。部分失败时保留已删除的
  行并重新读取目录，让未删除的条目回到真实状态。

## Alternatives considered

### 通过 SSH 执行 `rm -f` / `rm -rf`

这是最贴近 issue 字面意思的方案：直接在服务器上跑 `rm -rf -- <path>`，大目录
通常比逐条 SFTP 删除快，也能覆盖服务器对 SFTP REMOVE 的特殊限制。它最强的
理由是结果和用户在终端里手工执行命令完全一致，而且不依赖 SFTP 子系统的删除
能力。不采用的原因：Motty 的文件面板以 SFTP 为统一抽象，绕过它会引入 shell
差异（Windows OpenSSH 没有 `rm`）、命令引用和注入面、sudo/SCP 模式不一致，
也无法复用现有的取消、深度上限和路径穿越保护。issue 要的是删除方式，不是
换一条协议路径；先在同一条协议路径上把语义做对。

### 每次删除都先选方式，再确认

这能让「二次确认」和「删除方式」完全分离，流程最直观。它最强的理由是用户
在第一次确认框里只看到「删除」，第二次才做危险选择，误触成本更低。不采用的
原因：普通删除是最常用的路径，每次多弹一层会让高频操作变慢；把方式选择放进
第一次确认、只在强制删除时再确认一次，既保留安全默认值，也不给普通删除加
额外步骤。

### 移到回收站 / 回收站式删除

这比永久删除更安全，也符合桌面文件管理器的习惯。它最强的理由是误删可以恢复，
用户不需要理解 `rm -f`。不采用的原因：远端 SFTP 没有可移植的回收站协议，
本机 Windows、macOS 和 Linux 的回收站 API 也各不相同；本 issue 的反馈明确
要求 `rm -f` 式选择，回收站会变成另一个更大的跨平台功能。

### 把强制删除做成全局设置

用户设置一次后，之后所有删除都走强制语义，操作最快。它最强的理由是高频用户
不用每次选择。不采用的原因：强制删除会留下部分删除状态，把它变成持久默认值
会让一次误操作影响后续所有删除；本次选择只对当前确认有效，下一次回到普通
删除。

## Consequences

- 收益：删除确认框明确给出两种语义；普通删除保持原有安全行为；强制删除可以
  在一个坏条目后继续完成其余删除；删除中有转圈和进度；部分失败时列表和通知
  都反映真实结果。
- 代价：`sftpView` 多了一组删除计数和方式状态；确认框多了一行选择；强制删除
  可能留下部分删除的文件夹，因此失败路径仍要重新读取目录。它不是权限绕过，
  服务器拒绝的条目仍然无法删除。
- 测试：`internal/sftpclient/worker_test.go` 覆盖强制删除遇错继续、普通删除
  首错停止、缺失路径按已删除处理；`internal/workbench/sftp_delete_method_test.go`
  覆盖方式选择、强制删除二次确认、部分失败通知；`sftp_delete_spinner_test.go`
  覆盖分离窗口的删除 spinner；本机删除在 `sftp_local_delete_test.go` 覆盖
  强制删除跳过已消失条目。
