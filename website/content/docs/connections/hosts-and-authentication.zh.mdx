## 主机密钥

发送任何凭据之前，Motty 都会用自己的 `known_hosts` 校验主机密钥。遇到未知主机会弹出
带指纹的对话框，你可以信任一次或保存。密钥变化时会再次提示。

## 认证

Motty 支持：

- 正在运行的 SSH agent 中的密钥，
- 身份文件，包括 OpenSSH 用户证书（自动配对密钥旁的 `id_ed25519-cert.pub`），
- PuTTY `.ppk` 文件（版本 2 和 3，含 Argon2id 加密），
- 密码，
- keyboard-interactive 多轮问答。

一轮问答里有多个问题时（例如同一个 PAM 栈同时要密码和一次性验证码），会合并成一个
对话框，每个问题一个输入框。

### 证书与 agent

服务器出示主机证书时，只要其证书颁发机构已以 `@cert-authority` 记录在案就直接
连接；未知证书像未知主机密钥一样弹出指纹确认。主机还可以把本地 ssh-agent 转发给
远端 shell（按主机开关，默认关闭），远端的 `git push` 或 `ssh` 就能用本机已加载
的密钥。

### 一次性验证码

TOTP 和 HOTP 种子可以存进保险库，服务器要求验证码时自动填入。

### 测试连接

主机表单里有「测试连接」按钮，按表单当前填写的内容拨号，不保存主机。测试不会信任
未知的主机密钥，也不会向这样的服务器发送任何内容；登录需要表单之外的信息（例如一次性
验证码）时，结果是「未验证」，而不是失败。

## 登录之后

主机的「登录后命令」（在高级选项里）会在每个新终端准备好接收输入后自动输入，效果和
你手动输入一样，例如 `cd /srv/app` 或 `sudo -i`。它只能是一行，不会进入命令历史。

要切换到 root，可以把 `sudo -i` 设为登录后命令，再为密码提示添加自动填充规则：
「设置 > 终端 > 自动填充规则」里有「sudo 预设」（用该主机已保存的密码回答）和
「su 预设」（用保险库里的固定文本回答，例如 root 密码）。规则默认关闭，每个会话第一次
发送之前会先询问一次。

## 整理主机

主机可以分组、打标签和搜索。

### 导入

点击**导入 > 从其他软件导入**，选择来源客户端，再选取它保存的文件。Motty 读取每个
会话的名称、文件夹、地址、端口和用户；打不开的协议会计入“已跳过”。地址、用户和端口
都与已保存主机相同的主机会被略过。会话在连接目标之外保存的内容，只要客户端写了，也会
一并带过来：它要求的认证方式、X11 与 agent 转发、颜色、用到的私钥、经过的跳板主机，
以及它开的隧道。密码和密钥口令是例外：只有 Tabby 的会被导入，并且要等你输入它的
保险库密码（见 [Tabby 的保险库](#tabby-的保险库)）。其他客户端的密码请在导入后补到主机上。

| 来源 | 要选择的文件 |
| --- | --- |
| OpenSSH 配置 | `~/.ssh/config`（**导入 > 导入 SSH Config**） |
| PuTTY | Windows 上选注册表导出：`reg export HKCU\Software\SimonTatham\PuTTY\Sessions putty.reg`；Linux 和 macOS 上选 `~/.putty/sessions` 里的文件。 |
| Xshell | `.xsh` 会话文件，或 Xshell 导出的 `.xts` 压缩包。 |
| MobaXterm | 从会话面板导出的 `.mxtsessions` 文件，或 `MobaXterm.ini`。 |
| WindTerm | WindTerm 配置目录下 `terminal` 文件夹里的 `user.sessions`。 |
| Electerm | 在 Electerm 书签管理里导出的书签 JSON。 |
| Netcatty | Netcatty 主机页**导出**按钮得到的 CSV。Netcatty 自己的保险库是加密的，只有这份导出能被读取。 |
| Tabby | Tabby 数据目录里的 `config.yaml`：macOS 是 `~/Library/Application Support/tabby`，Windows 是 `%APPDATA%\tabby`，Linux 是 `~/.config/tabby`。 |

Electerm 和 Netcatty 会把已保存的密码以明文写进导出文件。Motty 不会导入它们，
并会在导入后提示；用完请删除该文件。

### Tabby 的保险库

Tabby 把密码、密钥口令以及你存进去的私钥放在一个**保险库**里：一整块用你在 Tabby
里设置的密码加密的数据。文件里有保险库时，导入会先问这个密码，然后才开始添加内容；
密码不对会被拒绝，不会去猜。解开之后：

- 密码和密钥口令会存进 Motty 自己的保险库，记在对应的主机或密钥名下，连接时不再询问。
- 存在 Tabby 保险库里的私钥会写到 Motty 配置旁的 `keys/` 目录，并加入密钥串。
- 跳板主机会变成跳板路由，会话里保存的隧道会变成端口转发。

如果关掉这个对话框，只会导入文件里明文保存的部分——会话、它们的路由和隧道——并提示
保险库没有解开。整个配置本身被加密的 Tabby 文件没有别的内容，关掉就什么都导不进来。

Tabby 在没有保险库之前把密码存在系统钥匙串里，那不是 Motty 能读取的；文件里没有
保险库时，导入后会说明这一点。

## 与 SSH 配置同步

导入只读取一次文件。要让 `~/.ssh/config` 和 Motty 双向保持一致，请打开
**设置 > 连接 > 与 SSH 配置同步**。

- 你在文件里新增或修改的 `Host` 会出现在 Motty，在 Motty 里新增或修改的主机会写回
  文件。主机地址、用户、端口和 `ProxyJump` 双向同步；`IdentityFile` 只会加入一次密钥串。
  `ProxyCommand` 只在主机第一次进入 Motty 时带过来，并等你确认（见
  [出站代理](/zh/docs/network/port-forwarding#出站代理)）。
  在 Motty 里停止跳板路由只影响 Motty 自己的连接；文件里仍保留 `ProxyJump`，终端里的
  `ssh` 依旧会经过跳板。
- 在 Motty 里创建的主机写进由 `# --- motty: begin synced hosts` 和
  `# --- motty: end synced hosts` 围起来的区块，位置在你的通用 `Host *` 区块之前。
  文件里的其余内容，包括注释和 Motty 不认识的设置，都保持原样。你自己写的主机在原处
  修改，并且只在它的区块只写了这一台主机时才会修改。
- 上次同步之后同一个字段在两边都被改过时，保留文件里的值。把主机从文件里删掉，它会
  留在 Motty 里并停止同步；在 Motty 里删除主机，会删掉 Motty 写的区块，而你自己写的区块保留。
- Motty 第一次改写某个文件时，会在它旁边保留一份以 `.motty-backup` 结尾的副本。写入
  过程中文件被别处改动时，绝不会覆盖。
- 同步发生在启动时、主机变化时，以及文件变化后你在窗口里点击时。不会轮询文件。
  **立即同步**可以随时手动运行，并列出无法映射的内容。

主机与别名的对应关系只保存在本机，不会随[云同步](/zh/docs/data/backup-and-sync)传到其他电脑。

## 保险库

保存的密码和密钥口令放在 AES-256-GCM 保险库里。保险库密钥保存在系统的密钥存储中；
如果设置了主密码，则由 Argon2id 主密码保护。保险库数据如何离开本机见
[备份与同步](/zh/docs/data/backup-and-sync)，安全模型见[安全](/zh/docs/reference/security)。
