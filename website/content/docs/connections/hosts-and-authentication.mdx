## Host keys

Host keys are verified against Motty's own `known_hosts` before any credential is
sent. An unknown host opens a dialog with the fingerprint; you can trust it once
or save it. A changed key is reported again.

## Authentication

Motty supports:

- keys held by the running SSH agent,
- identity files, including OpenSSH user certificates (a `id_ed25519-cert.pub` beside the key is paired automatically),
- PuTTY `.ppk` files, versions 2 and 3 (Argon2id encryption included),
- passwords,
- keyboard-interactive rounds.

A round that asks several questions, for example a password and a one-time code
from the same PAM stack, is shown as one dialog with one field per question.

### Certificates and the agent

Hosts that present a certificate connect without a prompt once their
certificate authority is on file as an `@cert-authority` line; an unknown
certificate is asked about with its fingerprint, like any unknown key. A host
can also forward the local ssh-agent to its shells (a per-host switch, off by
default), so a remote `git push` or `ssh` uses the keys already loaded on this
machine.

### One-time codes

TOTP and HOTP seeds can be stored in the vault and filled automatically when a
server asks for a code.

### Testing a connection

The host form has a **Test Connection** button. It dials the host as typed
without saving it. An unknown host key is never trusted by a test, and nothing
is sent to such a server; a login that needs more than the form holds, such as a
one-time code, ends as "not verified" instead of failing.

## After login

A host's **Command after login** (under Advanced) is typed into each new shell
once it is ready for input, as if you had typed it, for example `cd /srv/app`
or `sudo -i`. It is one line, and it stays out of the command history.

To switch to root, use `sudo -i` as that command and add an autofill rule for
the password prompt: **Settings > Terminal > Autofill rules** has a **sudo
preset** (answers with the host's saved password) and a **su preset** (answers
with a fixed text kept in the vault, such as root's password). A rule starts
off, and asks once per session before it first sends anything.

## Organising hosts

Hosts can be grouped, tagged and searched.

### Import

Open **Import > Import from** and choose the client, then the file it saved.
Motty takes each session's name, folder, address, port and user; protocols it
cannot open are counted as skipped. A host whose address, user and port are
already saved is left out. What a session saved beside the destination comes
along when the client wrote it down: the authentication it asked for, X11 and
agent forwarding, its colour, the private key it used, the jump host it went
through, and the tunnels it opened. Passwords and key passphrases are the
exception: only Tabby's are imported, and only once you type the passphrase of
its vault (see [Tabby's vault](#tabby-s-vault)). For the other clients, add
them to the host afterwards.

| Client | File to choose |
| --- | --- |
| OpenSSH config | `~/.ssh/config` (**Import > Import SSH Config**) |
| PuTTY | On Windows, a registry export: `reg export HKCU\Software\SimonTatham\PuTTY\Sessions putty.reg`. On Linux and macOS, the files in `~/.putty/sessions`. |
| Xshell | The `.xsh` session files, or the `.xts` archive Xshell exports. |
| MobaXterm | The `.mxtsessions` file exported from the sessions panel, or `MobaXterm.ini`. |
| WindTerm | `user.sessions` in the `terminal` folder of WindTerm's profile. |
| Electerm | The bookmarks JSON exported from Electerm's bookmark manager. |
| Netcatty | The CSV from the **Export** button on Netcatty's hosts page. Netcatty keeps its own vault encrypted, so only this export can be read. |
| Tabby | `config.yaml` in Tabby's data folder: `~/Library/Application Support/tabby` on macOS, `%APPDATA%\tabby` on Windows, `~/.config/tabby` on Linux. |

Electerm and Netcatty write saved passwords into the export in clear text.
Motty does not import them and says so after the import; delete the file when
you are done.

### Tabby's vault

Tabby keeps the passwords, key passphrases and any private key you stored in it
inside a **vault**: one blob encrypted with a passphrase you set in Tabby. When
the file has one, the import asks for that passphrase before it adds anything,
and a wrong one is refused rather than guessed at. Once it opens:

- Passwords and key passphrases go into Motty's own vault, under the host or the
  key they belong to, so connecting does not ask for them again.
- A private key kept in Tabby's vault is written to `keys/` beside Motty's
  configuration and added to the Keychain.
- Jump hosts become jump routes, and the tunnels a session saved become port
  forwards.

Dismiss the dialog and only what the file holds in the clear is imported — the
sessions, their routes and their tunnels — with a line saying the vault was left
locked. A Tabby configuration that is itself encrypted holds nothing else, so
dismissing it imports nothing at all.

Tabby before its vault kept passwords in the system keychain, which is not
Motty's to read; a file with no vault says so after the import.

## Syncing with your SSH config

Importing reads a file once. To keep `~/.ssh/config` and Motty in step both ways,
turn on **Settings > Connection > Sync with SSH config**.

- A `Host` you add or change in the file shows up in Motty, and a host you add or
  change in Motty is written to the file. The host, user, port and `ProxyJump`
  travel both ways; `IdentityFile` is added to the Keychain once. A `ProxyCommand`
  comes along once, with a host new to Motty, and waits for you to confirm it
  (see [Outbound proxy](/en/docs/network/port-forwarding#outbound-proxy)).
  Stopping a jump route in Motty only affects Motty's own connections; the file
  keeps the `ProxyJump`, so `ssh` in a terminal still goes through the jump host.
- Hosts made in Motty go in a block fenced by `# --- motty: begin synced hosts`
  and `# --- motty: end synced hosts`, placed before your general `Host *` blocks.
  Everything else in the file, comments and settings Motty does not know included,
  is left as it is. A host you wrote is edited in place, and only if its block
  names that host alone.
- When one field was changed on both sides since the last sync, the file's value
  is kept. Taking a host out of the file stops syncing it and keeps it in Motty;
  deleting a host in Motty removes the block Motty wrote, and leaves one you wrote.
- The first time Motty rewrites a file it keeps a copy beside it, named with
  `.motty-backup`. A file that changed while Motty was writing is never overwritten.
- It syncs at start, when hosts change, and when you click in the window after the
  file changed. Nothing polls the file. **Sync now** runs it on request and lists
  what could not be mapped.

The links between hosts and aliases are kept on this computer only, so they do not
travel with [cloud sync](/en/docs/data/backup-and-sync).

## The vault

Saved passwords and key passphrases go into an AES-256-GCM vault. The vault key
lives in the system secret store, or behind an Argon2id master password if you
set one. See [Backup and sync](/en/docs/data/backup-and-sync) for how vault data leaves
the machine, and [Security](/en/docs/reference/security) for the threat model.
