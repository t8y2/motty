---
title: MCP 服务器
description: 通过本地、带令牌保护的服务器，让外部代理使用你的会话。
---
HTTP MCP 服务器会把 Motty 中已打开的会话提供给 Claude Code 等外部客户端。
另一种“无需打开 Motty”方式则由客户端启动独立服务，使用已授权的保存主机。

它**默认关闭**，只监听回环地址，并要求 bearer 令牌。

## 启用

在 **设置 > MCP** 里打开 **允许外部代理（MCP）**。页面随后会显示地址和访问令牌，并
提供复制客户端配置的按钮。重置令牌会断开所有客户端。

两种方式各自提供客户端选择、配置预览和复制按钮，选择会分别保存。HTTP 配置
包含地址和令牌；独立服务配置则包含可执行文件与 `mcp-serve` 参数。
独立配置也会携带 `--data-dir` 指向当前配置目录，使用与当前窗口一致的授权主机与权限。

<Callout type="warn">
  拿到 HTTP 令牌的人就拥有你为 HTTP 服务选择的访问级别。不要把它放进共享配置。
</Callout>

### 访问级别

| 级别 | 客户端能做什么 |
| --- | --- |
| 观察 | 只读。 |
| 询问 | 低风险操作自动执行，其余操作需在 Motty 的 AI 助手面板批准；极高风险操作需要输入确认文字。 |
| 全部允许 | 包括高危操作在内的命令执行、文件读取、修改和删除都无需逐次审批。 |

切换到 **全部允许** 时会先显示风险确认框，确认后才保存并选中。取消或按 Esc 会保留原来的
访问级别。此权限对所有接入本地 MCP 服务的客户端及其可访问会话生效；切回 **观察** 或
**询问** 后，新的调用立即恢复对应限制。

已配置“全部允许”时，权限下方持续显示红色风险提示，HTTP 关闭时也会保留，说明下次启用
仍使用此权限。打开的多个窗口会同步显示同一 HTTP 权限。全部允许明确免除跨连接的审批，
但不会绕过策略显式禁止的操作，也不会扩大会话或授权主机的可访问范围。

## 工具

| 工具 | 作用 |
| --- | --- |
| `list_sessions` | 列出已打开的会话。 |
| `terminal_read` | 读取终端内容。 |
| `terminal_exec`、`terminal_exec_many` | 在终端里执行命令。 |
| `sftp_list`、`sftp_read` | 列出并读取远程文件。 |
| `sftp_write`、`sftp_remove` | 修改远程文件。 |

观察模式下只有读取类工具可用。

## 只支持 stdio 的客户端

`motty mcp-bridge` 把 MCP 通过 stdio 转发给正在运行的应用：

```sh
MOTTY_MCP_TOKEN=<令牌> motty mcp-bridge --url http://127.0.0.1:<端口>/mcp
```

令牌放在环境变量里，因为命令行参数会出现在进程列表中。

## 不开窗口

`motty mcp-serve` 是不需要窗口、也不需要端口的 MCP 服务器。代理需要时把它当作子进程
启动，代理结束它也结束；Motty 不必处于打开状态。在 **设置 > MCP** 里，**接入客户端**
会复制所选客户端需要的配置。

```sh
claude mcp add motty-hosts -- /path/to/motty mcp-serve
```

它使用你对代理开放的已保存主机，并用自己的连接。主机默认对代理关闭：在主机设置的
**高级**里打开 **允许 MCP 代理使用此主机**。这个选择只保存在本机，从其他设备同步来的
主机默认是关闭的。

| | |
| --- | --- |
| 工具 | 根据权限提供 `list_sessions`（你开放的主机）、`terminal_exec`、`terminal_exec_many`、`sftp_list`、`sftp_read`；“全部允许”另外提供 `sftp_write`、`sftp_remove`。没有可读的终端屏幕。 |
| 命令 | 通过 SSH exec 通道运行：没有终端，两次调用之间不保留任何状态。 |
| 只读 | 默认。选 **可运行命令** 后，代理可以运行评为低风险的命令。需要你批准的操作会被拒绝，因为没有人可以询问。 |
| 全部允许 | 先完成风险确认，才会保存并选中。在已授权主机上直接执行任意风险命令、写入或删除文件，不再请求审批。权限与 HTTP 分别设置，客户端下次启动服务时生效。 |
| 登录 | 使用 Motty 保存的内容：密钥、ssh-agent，以及已保存密码里的密码或密钥口令。设了主密码就读不出这些，请改用密钥。要求一次性验证码的服务器不能使用。 |
| 主机密钥 | 只接受 Motty 已信任的密钥。未知或已变化的密钥会被拒绝，请先在窗口里连接一次。代理自己绝不会信任密钥。 |
| 活动 | 设置 > MCP 列出最近 30 天的调用（主机、工具、命令或路径、结果）。不保存输出内容。 |

如果无法打开审计日志，就不提供任何服务。

独立服务的全部允许也有持续风险提示。修改权限后，请让客户端重启该服务；已经启动的
子进程继续使用启动时的权限。HTTP 权限则对切换后的新调用立即生效。

### 独立服务：文件传输与结构化结果

以下增强仅用于 `mcp-serve`，不改变 HTTP MCP、`mcp-bridge` 或内置助手的工具参数。
结果同时保留文本 `content` 和机器可读的 `structuredContent`。

| 工具 | 增强能力 |
| --- | --- |
| `terminal_exec` | 分别返回 `stdout`、`stderr`、`exit_code`、`duration_ms`、`truncated`、`timed_out`；可传本次调用的绝对 POSIX `cwd`。 |
| `sftp_list` | 按名称排序，支持 `offset`、`limit`（默认 500，最多 1000），返回 `total`、`next_offset`、`has_more`。 |
| `sftp_read` | 按字节 `offset` 或 `tail: true` 读取，单次最多 256 KiB；返回实际字节数、下一偏移、EOF 和截断标记。 |
| `sftp_stat` | 查询大小、类型、权限及修改时间，不跟随最后一级符号链接。 |
| `sftp_checksum` | 流式计算普通文件的 `sha256` 或 `sha512`，不把文件内容放进模型上下文。 |
| `sftp_upload`、`sftp_download` | 二进制安全的文件/目录传输；立即返回任务 ID，通过状态工具确认完成。 |
| `transfer_status` | 指定 `transfer_id` 查询，省略则列出本进程保留的任务。 |
| `transfer_cancel` | 请求取消任务；继续查询，直到任务结束。 |

命令输出合计保持现有大小限制。非零退出码是真实结果；断线、取消或超时没有可确认的退出码时
`exit_code` 为 `null`，并返回错误，而不是伪装成退出码 0。`cwd` 需要远端使用 POSIX shell；
目录切换失败不会继续执行命令。`terminal_exec_many` 保持原来的文本接口。

目录分页不是快照：目录改变时应重新读取。SCP 的属性和目录信息可能近似，结果标记 `approximate`。
读取普通文件时拒绝最后一级符号链接；UTF-8 模式会替换无效字节，使用 `encoding: "base64"`
可保留任意字节。偏移按原始字节计数，不按字符计数。`tail` 不能与非零 `offset` 一起使用。
校验期间发现大小或修改时间变化会报错；这不等于对持续变化的文件提供原子快照。

### 授权本机传输目录

远程“全部允许”**不会自动授予本机文件访问权限**。先在独立服务设置中确认“全部允许”，
再手动在 MCP 客户端启动参数中加入一个或多个 `--transfer-root`，重启服务：

```sh
motty mcp-serve --data-dir /path/to/motty-data --transfer-root /path/to/transfers
```

Windows 的参数数组示例（保留客户端原有的 `command` 和配置结构）：

```json
["mcp-serve", "--data-dir", "C:\\Users\\your-name\\AppData\\Roaming\\motty", "--transfer-root", "E:\\Transfers"]
```

目录必须已存在且是绝对路径；可重复该参数允许多个目录。未配置时不会提供上传、下载和取消工具。
`local_path` 是**运行 MCP 服务的电脑**上的完整路径，不是远端路径，也不是云端客户端的文件路径。
只允许根目录内的路径，拒绝路径中的本机符号链接。请使用自己控制的专用目录，不要让不可信进程
在传输过程中替换目录或链接；该限制不是操作系统文件沙箱。

上传调用示例：

```json
{"session":"<list_sessions 返回的主机 ID>","local_path":"E:\\Transfers\\archive.zip","remote_path":"/tmp/archive.zip","existing":"fail"}
```

目录需要 `recursive: true`；`remote_path`/`local_path` 指定完整目标，不是仅指定目标父目录。
`existing` 默认为 `fail`，显式选择 `replace` 才覆盖；SFTP 可选 `resume`。
按主机保存的 SFTP/SCP 配置选择协议；自动模式只在 SFTP 子系统不可用时回退。
SCP 不支持续传，`resume` 会明确失败，绝不静默重新上传。

任务状态包括 `queued`、`connecting`、`running`、`canceling`、`completed`、`failed`、`canceled`。
**返回任务 ID 或进度到 100% 都不代表成功，只有 `completed` 才表示已完成。**
每个 MCP 进程最多同时运行 4 个任务，保留最近 32 条记录；任务 ID 不跨进程复用。
传输有独立连接，取消不会中断其他命令或传输。服务退出会取消任务，记录不跨进程保存；
已提交的文件不会撤销，SCP 上传中断可能留下部分目标文件，SFTP 部分文件可能保留用于重试。
开始和最终状态写入原有审计日志，不记录文件内容；开始前无法写审计时不启动传输。

本批增强实现 issue #133 的文件/任务和单命令执行部分。独立 sudo 权限、主机/分组的创建修改、
快捷命令和笔记管理尚未提供；不通过这些工具绕过原有授权主机范围。
