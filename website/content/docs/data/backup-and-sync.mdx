## Backup

Export your state to one encrypted `.mottybak` file.

## Sync

Record-level sync works through:

- WebDAV
- S3-compatible storage
- a GitHub Gist
- a Gitee snippet

Records carry hybrid logical clocks, and deletions are kept as 90-day tombstones, so
several computers converge without one overwriting the other. The WebDAV form can
test the login before saving; the test makes the file's folders on the server if they
are missing. A configured service can sync now, or replace this computer's shared state
with the remote backup (**Restore remote**): changes made here and not yet synced are
lost, and a safety copy is kept next to `config.db` as `config.db.before-restore`.

### Jianguoyun (坚果云) and other WebDAV services

Motty creates the folders above the backup file when it uploads, but some services only
let their own app create top-level folders. Jianguoyun is one: first make a sync folder
in its web page or client, then set the file to `that-folder/backup.mottybak` (the
default, `motty/backup.mottybak`, works once a folder named `motty` exists there). The
password is the third-party app password from the Jianguoyun account's security
settings, not the login password.

### Gitee snippets

Create a personal access token at
[Gitee → Settings → Personal Access Tokens](https://gitee.com/profile/personal_access_tokens)
with the `gists` scope, choose **Gitee** in the sync settings, and leave the snippet
ID empty to create a private snippet on the first upload. The token is kept in the
saved-passwords vault, and the snippet holds the same encrypted backup as the other
services.

### Configure, test and enable

WebDAV, S3, GitHub and Gitee each have a row with **Edit** and **Enable / Disable**.
All four configurations are stored on this device. Only one service is enabled at a
time; enabling another preserves the previous service's settings, credentials and
remote backup. With all services disabled, automatic sync, Sync now and Restore remote
are inactive.

**Save** stores the edited account without enabling it or switching services. Editing
an enabled account updates the configuration used by subsequent syncs. Blank secret
fields retain that account's saved values, never another account's credentials. Each
service has its own backup password.

**Test configuration** checks the current form without saving or enabling it. It checks
authentication and decrypts any existing remote backup, then writes, reads back and
removes disposable test data. WebDAV and S3 use a random sibling object; GitHub and Gitee
use a separate temporary snippet. The real backup is not overwritten and a test snippet's
ID is never saved as the backup ID. Cleanup is still attempted after cancellation, and
cleanup failures are reported separately.

The test needs permission to create, read and delete the temporary object. Credentials
restricted to the exact backup object may fail the probe, while a writable probe cannot
rule out extra restrictions on the real object. Failed tests do not prevent saving;
the enabled service's status reports the result of actual syncs.

A successful test does not mean data has synced. Enable a service, then use **Sync now**
or automatic syncing; a completed sync displays its time. GitHub/Gitee record the backup
snippet ID only after the first real upload. Other devices need that same ID, file name
and backup password.

### Choose which hosts sync

Keep **Hosts and groups** enabled, turn on **Sync only selected hosts**, and select
which connections to exchange. Leaving this option off continues to sync all hosts.
Selecting a group selects its current hosts and those in its subgroups; hosts added
later must be selected separately. The selection belongs to this device and does not
change another computer's scope.

Unselected local connections and their own passwords, one-time codes and proxy
passwords are neither uploaded nor overwritten by remote edits, deletions or
**Restore remote**. Selected hosts carry the group metadata they need, and deleting
a selected host still propagates to other devices. A manual full backup continues
to include unselected connections.

Deselecting stops subsequent exchanges; previously uploaded copies remain on the
server. Shared credentials, SSH keys, jump routes, forwarding rules and trusted host
keys follow their own sync switches. They may contain information related to
unselected connections, so disable those categories separately when needed.

## What stays local

Tabs, window layout, shortcuts, fonts, key paths and cloud credentials are never
synced.
