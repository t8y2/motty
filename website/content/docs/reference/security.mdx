## What Motty does

- Host-key verification happens before any credential is sent.
- Saved passwords and passphrases use AES-256-GCM. The ordinary vault uses the system secret store or a local key file. With application lock enabled, the vault uses a separate key derived from the profile data key.
- AI provider keys are in the vault. Terminal context is redacted by default, and
  agent commands pass through the approval gate.
- The MCP server is off by default, loopback-only and bearer-token protected.
- MCP clients can read the local note library at the access level you chose;
  **Allow all** also lets them edit notes and write Markdown files already linked
  as notes.
- RDP certificates are pinned only after an explicit trust decision.
- Motty has no analytics. The optional update check contacts GitHub Releases and is
  off by default.

## Application lock

Open **Settings → Security → Application lock**, enter your master password twice, and wait for migration to finish.
The lock button appears above the local terminal in the lower-left corner. It locks every window using the same profile, including windows opened while locked. Existing connections keep running. After a restart, use the master password or an enrolled device credential to restore the workspace.

The master password protects connection records in the local configuration database and credentials in the vault.
Keep your master password for moving the profile to another computer. On supported devices you can also enroll
Windows Hello or macOS system verification. Changing the master password or turning protection off requires the current
password. Changing the password rewraps the profile data key. Turning protection off restores the ordinary connection database and re-encrypts saved credentials with the ordinary vault key. If migration is interrupted, reopen Motty and enter the master password to recover.

Connection settings and credentials are encrypted per record. Record types, sync timestamps, deletion markers, and the language and appearance preferences used by the lock screen remain visible. Command history (`history.db`), the AI database (`ai.db`), SSH known hosts, remote desktop certificate pins, session logs, external private-key files, and previously exported backups retain their own storage formats. Exported backups keep the password chosen at export. Local recovery copies archived during migration use the master password in effect when they were archived. Keep that password if you may need those copies after a password change.
To extract one, run `motty recover-profile-backup <archive> <new-directory>` in a terminal and enter the archive's master password. This writes the original file and any key material it needs into the new directory. If an individual historical copy exceeds 128 MiB, migration prompts you to handle that copy before changing the profile.

## What it does not do

The approval gate is a safety control, not a sandbox. VNC Authentication and Telnet
are not secure on their own; use SSH to carry them. Linux packages are not signed.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on the repository. Keep credentials,
host names and terminal output out of public issues.
