# Encrypted Credential Import Feasibility (2026-11-03)

This is a source-format investigation, not support for decrypting any of these formats. Only user-selected files may be read; no credential harvesting from installed clients, system secret stores or running processes is proposed. Decrypted values must follow the same explicit preview and vault-only commit contract as the plaintext imports.

| Client | Current Motty input | Credential evidence | Next validation / decision |
| --- | --- | --- | --- |
| PuTTY | Unix saved session or Windows Sessions `.reg` | PuTTY's FAQ says it does not remember an SSH login password. A saved proxy password is a different credential and may be stored in plaintext. | No SSH password adapter for stock PuTTY. Do not map proxy passwords or packet logs to host login passwords. [PuTTY FAQ](https://the.earth.li/~sgtatham/putty/0.84/htmldoc/AppendixA.html) |
| Xshell | `.xsh` or `.xts` | Xshell 8's export instructions say session passwords are unavailable when Clear Password is selected; otherwise they depend on the same Windows user or matching Master Password on the other computer. | Obtain versioned, synthetic exports with and without Master Password and Clear Password; check whether a documented, portable decrypt path exists and whether user-supplied Master Password suffices. No DPAPI, format guessing or source-machine account extraction without a separately reviewed contract. [Xshell 8 manual](https://www.netsarang.com/docs/Xshell8_manual.pdf) |
| MobaXterm | `.mxtsessions` or `[Bookmarks]` in `MobaXterm.ini` | Session export is documented separately from the password manager; saved credentials can be protected by a Master Password. The current bookmark parser sees no verified login-password field. | Compare versioned session exports with the documented full configuration/password-manager exports, including master-password and storage-location variants. Establish an unambiguous session-to-credential key before proposing an adapter. [MobaXterm documentation](https://mobaxterm.mobatek.net/documentation.html) |
| WindTerm | `user.sessions` | The author says `session.autoLogin` is encrypted and cannot be directly exported. Master Password protects saved auto-login information. | Obtain synthetic profile/version fixtures and the user's authorized master-password flow. Verify an official migration route or a reviewable implementation/test vector first; otherwise leave passwords unsupported. [Author's export answer](https://github.com/kingToolbox/WindTerm/discussions/69), [Master Password notes](https://kingtoolbox.github.io/2021/03/11/protection-master-password/) |

Each candidate adapter needs: exact source version/format, a user-controlled export, rights to read/decrypt, successful and wrong-password vectors, host mapping, non-SSH/key-auth exclusions, bounds on input and KDF work, and a security review. An unsupported version or failed authentication must leave existing Motty secrets untouched and explain the limitation without echoing input data.

The #351 attachment is public and may contain host or credential data; its CDN download was inaccessible during this investigation. The regression fixture in this worktree is synthetic and validates GB18030/UTF-8/UTF-16 behavior, not the attachment's as-yet-unverified exact code page. Acceptance against a sanitized copy of the report's file remains necessary.
