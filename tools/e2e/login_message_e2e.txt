# End to end: the login message sshd prints (PAM's MOTD, last login) reaches
# the terminal even when the tab opens a file panel on the same connection.
# sshd gives the message to the first session that starts a program and only a
# shell shows it; an SFTP subsystem or a command that gets there first drops it.
# The loopback fixture keeps that rule (E2E_LOGIN_MESSAGE) and claims an OpenSSH
# banner so the client runs its probes (E2E_ALLOW_EXEC). Connection sharing is
# turned off, so the split pane dials its own connection and opens its file
# panel at once, which is the order that used to lose the message:
#
#   go build -tags vivahead,dev -o /tmp/motty-head ./cmd/motty
#   cd tools/e2esshd && go build -o /tmp/e2esshd . && \
#     E2ESSHD_BANNER=SSH-2.0-OpenSSH_9.6 E2E_ALLOW_EXEC=1 \
#     E2E_LOGIN_MESSAGE='Welcome to e2e MOTD\nLast login: Sun Nov 22 08:32:48 2026' /tmp/e2esshd 2293 &
#   python3 tools/headless_drive.py "$(mktemp -d)" tools/e2e/login_message_e2e.txt
#
# What to look for: both panes show "Welcome to e2e MOTD" above "Last login",
# and the fixture's log says "login-message shown to shell" for each
# connection, never "dropped by".
