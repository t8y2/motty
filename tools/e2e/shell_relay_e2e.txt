# End to end: a host behind a bastion that only offers a shell. The bastion
# refuses every direct-tcpip channel (E2E_NO_DIRECT=1), so a plain jump route
# cannot reach the inner host. A route with "Relay through the jump host's shell"
# types the bastion's "Command after login" (export SWITCHED=1) into a shell on
# it, then runs the relay command there, and the inner host's SSH runs on that
# shell's input and output. The relay command insists on SWITCHED=1, so it only
# works when the command after login was typed first.
#
#   go build -tags vivahead,dev -o /tmp/motty-head ./cmd/motty
#   cd tools/e2esshd && go build -o /tmp/e2esshd . && cd ../..
#   E2E_NO_DIRECT=1 E2E_ALLOW_EXEC=1 /tmp/e2esshd 2291 &
#   E2E_ALLOW_EXEC=1 /tmp/e2esshd 2292 &
#   MOTTY_LANG=en python3 tools/headless_drive.py "$(mktemp -d)" tools/e2e/shell_relay_e2e.txt
#
# What to look for: the route reads "gate · shell relay"; both hosts' keys are
# asked in turn; VIA_RELAY_3 is on screen in the inner host's shell.
